⚠ The #1 Problem in Agentic AI

Agents operate without identity or governance

  • Shared credentials — every agent uses the same API key
  • No identity — agents act anonymously with no attribution
  • Shared knowledge — no scoping of context per user or role
  • Prompt-based policies — easily bypassed by injection
  • No audit trail — impossible to trace who did what

🔌 Model Context Protocol (MCP)

What is MCP?

  • Open protocol by Anthropic (Nov 2024)
  • Standardized tool interface for LLMs
  • JSON-RPC over SSE transport
  • Tools, Resources, Prompts primitives

What ContextWeaver Adds

  • Identity injection into every tool call
  • Credential vault integration
  • Hierarchical RAG context per user
  • Code-enforced security policies
  • Visual topology designer (Loom)

🔄 Agent Loop — 7 Steps

  1. 1 User sends message via Cerebro chat UI
  2. 2 LLM processes with system prompt + RAG context
  3. 3 LLM returns tool_calls array
  4. 4 Identity + credentials injected per user scope
  5. 5 Routed to correct MCP engine → plugin
  6. 6 Plugin executes against external API
  7. 7 Result streamed back via SSE to chat UI

🔐 Credential Vault

👤 User Key → 👥 Group Key → 🏢 Org Key

⚖️ Policy as Code

❌ Prompt-Based (Others)

  • Rules in system prompt text
  • Easily bypassed by injection
  • No compile-time enforcement
  • Inconsistent across models
  • "Please don't access X" 🙄

✅ Code-Based (ContextWeaver)

  • Enforced at middleware layer
  • Cannot be bypassed by LLM
  • Toggle switches in UI
  • Deterministic — same result every time
  • Request blocked before execution

🏢 Multi-Tenant Architecture

Multiple instances for complete separation — each tenant gets their own namespace, their own MCP engines, their own indexes, their own vault keys. Or share a single platform with logical isolation.

1:1 Dedicated — Complete Separation

  • Isolated AKS namespace per tenant
  • Dedicated Cosmos DB & Key Vault
  • Own MCP engines, RAG indexes, vault keys
  • Full data sovereignty — nothing shared
  • Independent scaling & compliance boundary

1:N Shared — Logical Isolation

  • Shared AKS cluster, K8s namespace separation
  • Partition key isolation in Cosmos
  • Scoped Key Vault policies per tenant
  • Tenant-scoped MCP engines & RAG indexes
  • Cost-efficient for SMB — same platform

🎬 Two Users, Same Request, Different Paths

"Book me a flight to NYC under $800"

👩‍💼 Sarah · Manager · Engineering
1️⃣ Agent injects: _user_email=sarah@acme.com, _role=manager, _groups=[engineering]
2️⃣ RAG search finds:
[P4 GROUP] "Engineering budget: $1000/flight"
[P3 ORG] "Approved airlines: United, Delta"
[P5 PERSONAL] "Sarah prefers aisle seat, United MileagePlus #MP789"
3️⃣ Vault resolves: Sarah's personal Amadeus API key (from user-level vault)
4️⃣ travel-proxy-call → searches United flights → finds $750 aisle seat
5️⃣ payments-charge → $750 on Sarah's Visa 4242 → ✅ BOOKED
6️⃣ email-send → itinerary to sarah@acme.com with MileagePlus# attached
👨‍🎓 Tom · Viewer (Intern) · Engineering
1️⃣ Agent injects: _user_email=tom@acme.com, _role=viewer, _groups=[engineering]
2️⃣ RAG search finds:
[P4 GROUP] "Engineering budget: $1000/flight"
[P3 ORG] "Interns require manager approval for travel"
[P5 PERSONAL] — none configured
3️⃣ Vault resolves: Org-level shared Amadeus key (Tom has no personal key)
4️⃣ travel-proxy-call → searches flights → finds options
5️⃣ payments-charge → ❌ BLOCKED
read_only mode for viewer role → "Write operations blocked"
6️⃣ Agent responds: "I found a $680 Delta flight. Your role requires manager approval to book. Sending approval request to your manager..."
